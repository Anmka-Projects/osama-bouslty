# Register API — Saudi mobile phone (`phone`)

مواصفة التحقق من رقم الجوال في **التسجيل** لتتوافق مع تطبيق Flutter (أرقام سعودية محلية).

## الملخص

| البند | القيمة |
|--------|--------|
| الحقل في الطلب | `phone` |
| التنسيق | رقم سعودي محلي يبدأ بـ `05` |
| الطول | **10 أرقام** بالضبط (بدون مسافات أو شرطات) |
| الأحرف المسموحة | أرقام ASCII فقط `0–9` |

## قاعدة التحقق (Backend)

- يجب أن يكون الحقل إما **غير مرسل** أو **فارغ** (إن كان الاختياري عندكم)، أو يطابق النمط التالي بعد `trim()`:
- **Regex مقترح:** `^05\d{8}$`
  - يعني: `05` ثم **8** أرقام إضافية = **10** أرقام إجمالاً.

### أمثلة صالحة

- `0501234567`
- `0555123456`

### أمثلة غير صالحة

| المدخل | السبب |
|--------|--------|
| `5012345678` | لا يبدأ بـ `05` |
| `051234567` | أقل من 10 أرقام |
| `05123456789` | أكثر من 10 أرقام |
| `05 1234 5678` | يحتوي على مسافات (يجب الرفض أو التطبيع حسب سياسة واحدة موحّدة) |
| `+966501234567` | صيغة دولية — خارج نطاق هذا الحقل إن كان العقد المحلي فقط `05…` |
| `٠٥١٢٣٤٥٦٧٨٩` | أرقام عربية — يُفضّل الرفض أو تحويل موحّد إلى ASCII |

## توصيات التطبيع (اختياري لكن مُستحسن)

1. قبل التحقق: `trim()` على السلسلة.
2. إزالة مسافات/شرطات/أقواس إن وُجدت، ثم التحقق من النمط.
3. تخزين في قاعدة البيانات بنفس الصيغة المتفق عليها (مثلاً دائماً 10 أرقام تبدأ بـ `05`).

## استجابة الخطأ (مقترح)

عند فشل التحقق من `phone` في `POST` التسجيل:

- **HTTP:** `422 Unprocessable Entity` (أو `400 Bad Request` إن كان معيار المشروع كذلك).
- **جسم JSON (مثال):**

```json
{
  "success": false,
  "message": "Invalid phone number. Use a 10-digit Saudi mobile starting with 05.",
  "errors": {
    "phone": ["The phone must be a 10-digit Saudi mobile number starting with 05."]
  }
}
```

(النص الفعلي للرسالة يمكن توحيده مع رسائل التحقق الأخرى في المشروع.)

## مرجع التطبيق (Flutter)

- الطلب يرسل `phone` كسلسلة نصية في جسم `POST /auth/register` (مع بقية الحقول: `name`, `email`, `password`, …).
- يُفترض أن يطبّق التطبيق نفس القاعدة على الواجهة: `^05\d{8}$` وطول 10.
